# Первый блок сохраняемых связей памяти

Это развитие существующих `relationships.py`, `storage.py`, `lifecycle.py`
и `coordinator.py`. Чистые валидаторы связей и ссылок на людей сохранены.
Новых промежуточных модулей нет; используется прежняя `memory.db`.

## Что делает блок

Координатор может сохранить явно переданную связь между двумя уже
существующими воспоминаниями одного участника. Пример: человек связал
свою цель и событие одной темой. Запись содержит тип связи, уровень
подтверждения, собственный зарегистрированный источник, дату создания
и отпечатки версий обоих фактов. Тела фактов в таблице связей не дублируются.

Типы отношений остаются прежними: `same_topic`, `same_event`, `related_event`,
`involves_person`, `family_relation`, `social_relation`. Подтверждённая связь
требует явного подтверждения от доверенного вызывающего кода; предполагаемая
связь сохраняется как `hypothesis`. Гипотетические факты не превращаются
в подтверждённое утверждение через связь.

## Права, источники и изменения

- Сохранение проходит через `coordinator.remember_relationship`: проверяются
  политика доступа и разрешения источников. В одной транзакции повторно
  проверяются сохранённое согласие, полный актуальный снимок каждого факта,
  принадлежность и действующие источники фактов и самой связи.
- Повтор идентичного запроса с тем же источником возвращает прежний ID,
  сохраняя исходную дату. Другой смысл или новая версия требуют нового
  подтверждающего сообщения; прежний источник не переиспользуется для
  автоматического оживления старой связи.
- Исправление содержания факта переводит связанные записи в
  `review_required`. Они не попадают в текущий контекст. Возврат к прежней
  формулировке сам по себе не включает связь обратно. Подтверждение
  неизменившегося факта не портит действующую связь.
- Удаление факта удаляет относящиеся к нему связи. Удаление или истечение
  источника связи очищает её, даже если оба факта имеют самостоятельные
  действующие основания. Удаление дубля не переносит его связи на другую
  запись автоматически. Исходная переписка не переписывается.
- Сроки берутся из зарегистрированных сообщений: 365 суток от их исходных
  дат, без продления временем сохранения связи. Отзыв согласия блокирует
  чтение и запись; сам по себе он не меняет прежнюю политику удаления данных.

## Чтение через координатор

`read_context(..., include_relationships=True)` возвращает связи только
между уже отобранными фактами. Он не расширяет контекст скрытыми фактами
и не предоставляет доступ к чужому участнику через идентификатор.
Источник самой связи и текущие источники обоих фактов также должны входить
в проверенный разрешённый набор. Проверка сохранённого согласия и данных
связи выполняется в согласованной транзакции чтения. Гипотеза остаётся
помеченной гипотезой.

Набор ограничен десятью связями в контексте, максимум пятьюдесятью
отобранными ID для прямого чтения. Фильтрация разрешений выполняется
до ограничения результата. Обычный вызов без нового флага сохраняет
прежний формат ответа; чтение старой базы не создаёт таблицу связей.

## Граница готовности

В этой части нет автоматического извлечения связей из свободного диалога,
разрешения личностей упомянутых людей, пересчёта зависимых психологических
выводов или новой команды участника. Рабочий `bot.py` этот API ещё не
вызывает. Самостоятельного слияния в `main` и пересборки Bothost нет;
наблюдение почасового резерва продолжается на прежнем выпуске.

Следующий шаг — подключить источник предложений связей к координатору,
согласовать явное подтверждение и отделение гипотез, затем проверить
ограниченный сценарий свободного диалога с исправлением исходного факта.
Только после этого принимать соответствующее поведение рабочего бота.

Тесты нового блока проверяют сохранение, повтор, изоляцию, источники,
согласие между проверкой и транзакцией, версии, исправления, удаления,
истечение срока, объединение дублей и включение базы со связями в полный
семифайловый снимок. Они выполняются на временных тестовых данных.
